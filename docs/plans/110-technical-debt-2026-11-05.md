"남은 기술부채 확인 후 수정 계획" 요청. main은 깨끗하고 CI도 통과한다. `alembic check`·pip-audit·프로덕션 npm audit 모두 0건이다(109의 미검증 항목 하나 해소). TODO·`any` 같은 고전적 부채는 이번에도 없다.

- **C5에 프론트를 포함했다.** `dcaScenarioProjection`·`savingsProjection`이 같은 명목 공식이라 화면 곡선이 어긋날 뻔했다. 절약 시뮬레이터 수치도 조금 내려간다(월 10만·7%·10년 약 1,730만→1,711만).
- **`data_incomplete`는 응답에 싣지 않는다**(`exclude=True`). 캐시 시간 결정에만 쓴다. 일부 후보가 빠지면 10분만 저장하고 stale 키에 넣지 않는다.
- **C4 전 항목 공통**: 안내 문구 "시세를 가져오지 못한 후보 N개를 빼고 계산했어요". 상장 직후라 시세가 계속 없는 ETF를 등록한 사용자에게는 이 문구가 계속 보이고 10분마다 다시 계산한다.

### 동작이 바뀌는 것

- **필요 수익률이 오른다**(복리 기준). 목표 달성 판정·추천 하한도 함께 바뀐다.
- **60대·50대에 안전자산 후보가 없으면 현금성 비중이 크게 나온다**(상한을 지키므로). 예전엔 100% 주식이었다.
- **IRP**: 채권 시세가 없으면 합성 현금성으로 대체하고, 그래도 못 지키면 추천하지 않는다.
- **자산 목표를 달성해도 배당 목표가 있으면 추천이 계속 나온다.** "이미 달성" 안내는 이 경우 나오지 않는다.
- **DCA**: 수익률 0%·적립액 0원도 설정 완료로 본다.
- **예수금 부족 알림**: 사용자 단위로 합산해 판정하고 알림은 한 건만 낸다. 동기화 전 계좌와 실환율이 없는 달러 예수금은 판정에서 뺀다.

### 이번에 안 고친 것

- **미리보기와 추천의 기대수익률 척도**: 추천은 축소추정 CAGR, 미리보기는 원본 CAGR이다. 같은 비중이어도 값이 다르다(예: 14.42 vs 15.55). 코드 주석이 의도로 명시해 두어 판단이 필요하다.
- **전체 자산 IRP 전용 사용자의 30% 하한**(#18): 기간별 경로와 다르지만 의도일 수 있어 뒀다.
- **시장 간 거래일 차이**: 시계열에 날짜가 없어 위치로만 맞춘다. 날짜 키 정렬은 이관.
- **낮은 순위 보고 건**: DCA 초기값 일부 계좌만 동기화(#20), 곡선에서 이번 달 누락(#21), 잔액 0 표시(#23), 초기 달성 불가 계획의 실제 전망 숨김(#24), 혼합 포트폴리오 달러 예수금(#25).

### 검증하지 못한 것

- 실제 Yahoo·Naver 응답, 실사용자 후보 조합. 표는 고정 데이터·합성 시계열 기준이다.
- 브라우저·실기기 확인. 실주문은 없다(추천·표시 경로).

| 항목 | 입력 | 전 | 후 |

### 계획과 달라진 것

- **D2 `_tax_items` 타임아웃은 넣지 않았다.** `wait_for` 취소가 공유 세션의 commit 중에 떨어지면 세션이 깨진다(`overseas_realized_service`의 기존 주석과 같은 이유). 대신 조회 실패 결과를 2분 캐시해 장애 중 홈을 열 때마다 계좌별 20초씩 기다리지 않게 했다. 첫 로드는 여전히 느릴 수 있다.
- **D1 재시도 상한 3회**: 수신 채널이 없는 사용자도 실패로 잡히므로, 3시간 시도 뒤 다음으로 넘어간다. 그 사용자에게는 끝내 안 간다.
- **D5 주간 잡은 넣지 않았다.** 당일 dedup뿐이라 다시 돌리면 중복 발송된다.
- **D7 쿼리 키 분리**: 값 형태가 달라 `rebalancingHistoryPages`를 새로 뒀다. 영속 캐시의 옛 배열 값을 무한 쿼리가 읽으면 깨지기 때문이다.
- **D8**: 잘렸으면 해당 계좌를 미집계 목록에도 넣어 `PARTIAL`로 표시한다. 합계(`output2`)가 있으면 잘린 것으로 보지 않는다.

### 동작이 바뀌는 것

- **시장 신호 등급 변경 알림이 실제로 나가기 시작한다.** 지금까지 대부분 유실됐다면 사용자 입장에선 새 알림처럼 보인다. 배포 직후 첫 실행은 저장만 한다.
- **보충 잡**: 슬립으로 놓친 월간 리포트가 1~3일 낮에 늦게 도착할 수 있다. 메일 발송 실패 사용자는 매시 재시도된다.
- **`PUT /assets/{id}`에 `is_active=false`를 보내면 400**: 현재 프론트는 보내지 않는다.
- **`/rebalancing/history`**: `skip` 추가. 기존 호출은 그대로 동작한다.

### 검증하지 못한 것

- **실제 Render 슬립 복구**: 보충 잡은 시간 판정과 호출만 테스트했다. 스케줄러가 깨어난 뒤 실제로 도는지는 배포 로그로 확인해야 한다.
- **`release_session` 커넥션 반환**: 실DB 풀로 재지 못했고 commit 호출 순서만 고정했다.
- **KIS 실응답**: D8의 `output2`가 리스트로 오는지, D9의 `frcr_dncl_amt_2` 유무.
- 브라우저·실기기 확인.
