## 배치 A — 116 회귀 (백엔드)

- **A1 ✔ nestlio 전액 출금 후 매일 동기화 실패**
  - `external.py`가 `manual_amount`를 0으로 만들면 `ManualProvider`가 "미설정"으로 보고 `BadRequestError`를 던졌다.
  - 수정: `None`만 미설정으로 본다. 입력 스키마는 0을 받지 않으므로 0은 실제 잔액이다.
- **A2 ✔ 계좌 간 이전이 XIRR 투자금으로 두 번 잡힘** (사용자 결정: 잔액 감소 상쇄)
  - 입출금 기록 없이 A를 비우고 새 계좌 B로 옮기면 A·B의 첫 스냅샷이 모두 기초 유출이 된다.
  - 수정: `offset_transfer_openings`가 B 첫 스냅샷일 ±7일 안에서 먼저 있던 계좌들의 평가액 감소분을 계산해 B의 기초 잔액에서 뺀다.
    - 감소분에서 기록된 출금은 제외한다.
    - 한 번 상쇄에 쓴 감소분은 다시 쓰지 않는다.
    - 상쇄액은 B의 기초 잔액을 넘지 않는다.
  - 창 스냅샷은 `get_transfer_window_snapshots`가 한 번에 조회한다.
  - 사용자 전체 XIRR(`calc_xirr`)에만 적용한다. nestlio 계좌 단위 조회에선 이전도 그 계좌의 실제 유입이다.
- **A3 ✔ 기초 잔액 0이면 첫 스냅샷 당일 입금이 버려짐**: 기초 잔액을 넣었을 때만 당일 이전 거래를 버린다.
- **A4 배당 계좌 범위 불일치**
  - 연동 계좌가 없는 포트폴리오에서 개요는 합산 제외 계좌의 보유분을 포함하는데, 배당 요약은 제외했다.
  - 수정: 개요가 쓴 계좌 id를 명시해 넘긴다.

## 배치 B — 백엔드 실버그 (미감사 영역)

- **B1 ✔ DART corpCode 실패가 기억되지 않음**: 국내 종목마다 30초 타임아웃 ZIP 다운로드를 락 뒤에서 반복했다.
  - 키별로 실패를 10분간 기억한다.
  - 쓰이지 않던 전역 `dart_circuit`은 삭제했다. 키가 사용자마다 달라 한 사용자의 잘못된 키가 모두를 막으면 안 되기 때문이다.
  - 키를 저장하면 배당 캐시를 무효화하고 실패 기록을 초기화한다.
- **B2 ✔ 챌린지 달성 알림 소실**: 발송이 실패해도 먼저 COMPLETED로 바뀌어 재실행(ACTIVE만 조회)에서 빠졌다. 이제 알림이 나간 뒤에만 완료로 바꾼다.
- **B3 ETF 겹침 분석**: 프로필 조회가 일부 실패한 결과를 하루 캐싱하지 않는다(`get_etf_profiles_with_status`).
- **B4 인사이트 stale**
  - 매도기록 CUD가 `insights_key`를 무효화한다.
  - 실현손익 조회에 실패하면 짧은 TTL(`TTL_INSIGHTS_DEGRADED`)로 저장한다.
- **B5 탈퇴 app_state**: FK가 없는 `app_state`에서 키에 user_id가 들어간 행을 함께 지운다(만료 없는 목표 달성 기록).
- **B6 정리**
  - positions 라우트에 rate limit을 걸고, 연동 계좌의 저장을 거부한다(화면도 이미 읽기 전용).
  - 거래·매매 목록에 id tiebreaker를 추가하고, 연도 필터를 범위 조건으로 바꿨다.
  - KIS 리터럴을 enum으로 바꿨다.
  - 인플레이션 신호가 history 캐시를 공유한다.
  - 실행 중(토큰 소비) leg는 `actionable=false`·`IN_PROGRESS`로 처리한다. 예전에는 만료나 취소 가능으로 보였다.
  - sweep에서 건너뛴 leg의 FOR UPDATE 락을 즉시 해제한다.

## 배치 C — 프론트

- **C1 ✔ 알림 이메일 덮어쓰기**: 입력칸이 로그인 이메일로 채워져, 저장하면 따로 설정한 주소를 덮어썼다.
  - 저장값으로 채우고, 값이 도착하면 `key`로 다시 마운트한다.
  - 로그인 이메일은 placeholder로만 보인다.
- **C2 ✔ 푸시 끄기가 재시작 후 풀림**
  - 사용자별 끈 기록을 남긴다(`constants/storageKeys.ts`의 `pushOptOutKey`).
  - 끈 기록이 있으면 자동 등록을 건너뛴다. 다시 시도하면 기록을 지운다.
- **C3 ✔ 거부 후 "다시 시도"가 "확인 중..."에 멈춤**: 리스너를 권한 확인 전에 붙이고, 재시도 예외를 `error`로 처리한다.
- **C4 ✔ 생체인증 토글이 다시 그려지지 않음**: `isEnabled`를 state로 바꿨다.
- **C5 기기 공유·정리 중복**
  - 목표 마법사 자동 표시 플래그를 사용자별로 바꿨다.
  - 탈퇴 정리는 `useLogout` 한 경로로 합쳤다. 예전 사본에는 동기화 상태 초기화가 빠져 있었다.
  - 탈퇴 때 사용자별 키를 삭제한다.
  - 가입 직후에는 생체인증을 다시 묻지 않는다.
- **C6 죽은 UI 제거**
  - 아이디 찾기 페이지와 `/auth/find-account`(백엔드가 고정 문구만 반환)를 제거했다.
  - 가입 이름 입력도 제거했다. 어디에도 표시되지 않고, 이메일 인증 가입에선 저장되지도 않았다.
  - rate limit 위조 방지 테스트는 대상을 공개 플랜 미리보기로 바꿨다.
- **C7 정리**
  - `fmtKrw`·`fmtKrwShort`의 음수 반올림을 대칭으로 맞췄다.
  - DART 키를 저장하면 입력칸을 비우고, 빈 값이면 저장할 수 없게 했다.
  - 맨 `toLocaleString`을 `fmtKrwPrice`로 바꿨다.

## 보류·이관

- 116 보류 항목은 그대로 둔다: 분산도 점수 체계, 키움 소수 수량, biometric 플러그인 교체, 소유자 확인 리팩터, period_purchase 하한, 600줄 파일.
- `periodic_catchup`과 월간 잡이 겹칠 수 있다. 현재 규모에서는 가능성이 낮아 claim 원자화는 별도로 다룬다.
- 취소 실패 후 표시되는 "실행 결과 확인 필요" 문구: leg에 취소 시도를 기록해야 하므로 스키마 변경이 필요하다.
- `growlio_biometric_enabled`는 기기 단위로 둔다. 기기 잠금 성격이고, 가입·로그인은 이번 세션 인증으로 통과한다.
