# 88. 추천 설정이 추천 비중에 반영되지 않음 — 캐시 경합 (2026-10-28)

> 상태: **A·B 완료**.

## Context

리밸런싱 › 목표 조정 › 추천 › "추천 설정"에서 투자성향·종목당 최대비중 등을 저장해도 추천 비중이 그대로라는 제보.

저장 경로는 정상이었다. 모달이 `PUT /settings/goal-recommendation-options`로 DB에 저장하고, 백엔드가 추천 캐시 키를 지우고, 프론트가 `["goal-recommendation"]`을 무효화한다. 계산도 저장된 설정을 옵티마이저에 넘긴다.

원인은 **계산 도중 저장**이다. 추천 계산은 시작할 때 설정을 읽고 수십 초 걸린다.

1. **single-flight 합류**: 진입 시 콜드 계산이 도는 동안에도 "추천 설정" 버튼이 열려 있다. 그때 저장하면 저장 직후 재요청이 같은 락(`lock:{key}`)을 기다리다가 옛 설정으로 계산한 결과를 받는다.
2. **늦게 끝난 옛 계산이 덮어쓰기**: 락 TTL(15s)보다 계산이 길면 대기자는 새로 계산한다. 그런데 나중에 끝난 옛 계산이 1h 키와 stale 키(1일)에 옛 결과를 다시 쓴다. 그 뒤 방문은 계속 옛 비중을 본다.
3. **stale 백그라운드 갱신(plans/66)**도 같은 방식으로 덮어쓴다.

Render 무료 플랜은 슬립할 때마다 in-memory 캐시가 비어서 진입이 거의 매번 콜드 계산이 된다. 그래서 이 경합이 자주 일어난다. 기간별·연령대 캐시와 포지션 변경 sync 무효화에도 같은 경합이 있었다.

## A. 추천 캐시 세대 토큰 (완료)

- `cache_keys.py`: 사용자별 `goal_recommendation_gen` 키(랜덤 uuid, 7일)를 추가했다. 전체/stale/기간별/연령대 결과 키에는 세대가 들어간다. `invalidate_goal_recommendation_caches`는 현재 세대 키를 지우고 세대를 새 값으로 바꾼다. `invalidate_asset_account_caches`(positions_changed)도 이 함수를 쓴다.
- 옛 계산은 시작할 때 잡은 세대 키에 쓰므로, 아무도 읽지 않는 키에만 남는다. 새 세대의 락 키도 달라서 저장 직후 요청이 옛 계산을 기다리지 않는다.
- **세대는 설정을 읽기 전에 잡는다.** 엔드포인트 3곳과 백그라운드 갱신이 세대를 먼저 읽고 넘긴다. 설정을 읽은 뒤에 잡으면 그 사이 저장된 새 세대에 옛 결과가 들어간다. 추천 변화 알림 job은 생략했다(서비스가 내부에서 잡음, 주 1회라 영향이 작음).
- 축출이나 재시작 후 옛 세대와 겹치지 않도록 고정 기본값 대신 랜덤 값을 쓴다.

## B. "전체" 탭에 적용된 설정 표시 (완료)

`RecommendationOverallTab`에 "적용된 설정: 투자성향 · 종목당 최대 n%"를 추가했다(응답에 이미 있던 필드). 설정이 반영됐는데도 비중이 그대로인 경우와 구분할 수 있다. 예를 들어 보수적 성향은 CAGR 기간과 무관하고, 후보가 적으면 `max(max_weight, 1/n)`로 상한이 완화된다. 기간별·연령대 탭은 원래 투자성향을 보여줬다.
