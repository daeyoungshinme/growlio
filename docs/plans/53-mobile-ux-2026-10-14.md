# 53. 모바일 가독성·사용성 개선 (2026-10-14)

> 자기완결 계획서. 실행 전 `git status`/`git diff`로 아래 파일이 다른 세션에서 바뀌지 않았는지 확인하고, file:line이 현재 코드와 다르면 **코드를 우선**한다.

## 배경

사용자 요청: "모바일 사용자 측면에서 가독성·사용성을 생각해 UI/UX 개선 계획".

이전 모바일 라운드(07-13 · 07-20 · 07-22 · 08-06 · 계획50 X1~X9)는 대부분 완료됐다. 계획50에 남은 것은 "Hero 도넛 고정폭"과 "390px 실기기 검증" 두 가지다. 이번에는 현재 코드를 기준으로 3개 영역을 새로 감사했다(코드 리딩 기반, 390px 가정).

- 홈·레이아웃·공통
- 자산·리밸런싱
- 계획·설정·인증

**이미 잘 되어 있음 — 재제안 금지**
- `text-[9~11px]` 클래스 0건
- 모든 `<table>`에 `sm:hidden` 모바일 카드 대체
- 금액 입력 대부분 `inputMode` 지정, `fmtKrwPreview` 미리보기
- Modal은 바텀시트 + `max-h-[85dvh]` + 44px 닫기
- `Tabs`는 44px
- 실행 모달 2단계 확인, 계좌 삭제 `ConfirmModal`
- 보유종목 카드 탭 펼침 + 페이지 스크롤 가상화
- 고정 실행 버튼은 IntersectionObserver로 표시

**남은 문제의 축**
1. 확인 없는 실자금·데이터 파괴 동작
2. 입력 진행이 사라지는 동선
3. hover 전용 정보(`title`은 터치에서 안 보임)
4. 좁은 폭 레이아웃·저대비
5. 3~4단 탭 중첩과 긴 화면
6. 네이티브 셸(상단 안전영역·키보드)

## Phase B — 가독성 저위험 스윕 (미착수)

### 홈

## Phase D — 실기기 확인 후 착수 (사용자 APK 확인 대기)

**상단 안전영역**
- 근거:
  - `index.html`이 `viewport-fit=cover`
  - targetSdk 36(Android 15+ edge-to-edge 강제)
  - `safe-area-inset-top` 사용 0건
  - Capacitor StatusBar 설정 없음
- 확인할 것: 상태바와 `AppLayout` 헤더·당겨서새로고침 인디케이터·`TopLoadingBar`가 겹치는지
- 겹치면: 루트에 `pt-[env(safe-area-inset-top)]`, 인디케이터·로딩바 오프셋

**키보드가 모달 하단 버튼을 가림**
- 근거: `windowSoftInputMode`·`interactive-widget` 없음, 버튼이 스크롤 콘텐츠 끝에 있음
- 대상: `GoalSettingWizard`, `InvestPlanPage` 편집 모달 2곳, `ChallengeFormModal`
- 가리면: Modal에 sticky footer 슬롯 + viewport `interactive-widget=resizes-content` 또는 `adjustResize`

**스크롤 잠금**
- `useModalBehavior`가 body를 잠그지만 실제 스크롤 요소는 `<main>`
- `h-screen`(100vh) → `h-dvh` (PWA)

**A1 뒤로가기 확인**
- 확인창이 떠 있을 때 뒤로가기 → 확인창만 닫히는지
- 편집 모달 위 확인창에서도 같은지
