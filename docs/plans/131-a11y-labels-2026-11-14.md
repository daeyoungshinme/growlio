# 계획 131 — 폼 label 접근성 (2026-11-14)

## Context

계획 119에서 "접근성 label 약 38개, 하드코딩된 라벨 클래스"를 별도 계획으로 넘겼다(근거 목록은 남지 않음). 다시 셌다: TypeScript AST로 `src/**/*.tsx`의 `<label>` 128개를 훑어, `htmlFor`도 없고 `input`·`select`·`textarea`도 감싸지 않은 label이 **31개**였다(119의 38개는 이후 리팩터에서 일부가 사라진 것으로 보임). 이런 label은 화면에 글자만 있고 스크린리더가 입력의 이름으로 읽지 못하며, label을 탭해도 입력에 포커스가 가지 않는다.

## 처리

| 유형 | 처리 | 위치 |
|---|---|---|
| 입력 하나의 라벨 (22곳) | `useId()` 기반 `htmlFor` + 컨트롤 `id` | `GoalRecommendationOptionsModal`(7), `AlertAutoModeSection`(5), `AlertModeSection`, `AlertQuickDcaSection`(2), `AlertTriggerSection`, `BacktestTab`(2), `TaxOptimizationCard`, `UnifiedPortfolioEditor`(이름), `ForgotPasswordPage` |
| 선택 상자↔직접 입력 전환 | 둘 다 같은 id (동시에 렌더되지 않음) | `TickerSearchField`, `TransactionTickerField` |
| 원화↔달러 금액 전환 | `htmlFor`가 보이는 쪽 id를 고름 | `TransactionForm`, `TransactionModal` |
| 여러 입력을 묶는 제목 | label → `<p id>` + 묶음에 `role="group"`/`radiogroup` + `aria-labelledby`, 이름 없는 입력엔 `aria-label` | `BankAccountModal`(잔액 원·USD), `StockDepositFields`(예수금), `PortfolioAccountSelector`(체크박스), `UnifiedPortfolioEditor`(기준 자산 라디오) |
| 입력 없는 표시·섹션 제목 | `<p>`/`<h3>` | `SettingsPage`(로그인 이메일), `UnifiedPortfolioEditor`(종목 및 비중), 연령대(출생연도가 있어 선택 상자가 없을 때) |

`AutoExecutionAccountPicker`는 선택 상자가 렌더될 때만 쓰는 `id` prop을 받는다(계좌 0·1개면 텍스트 표시).

## 라벨 클래스

- `constants/inputStyles.ts`에 `FORM_LABEL_XS` 추가(작은 설정 모달). 기존 `FORM_LABEL`과 같은 문자열을 직접 쓰던 29곳(`BankAccountModal` 6, 로그인·가입·재설정·비밀번호 찾기 페이지, 알림·추천 모달, 목표 마법사)을 상수로 바꿨다.
- `mb-2` 변형·`text-gray-600` 변형처럼 상수와 다른 클래스는 시각 변화가 생기므로 그대로 뒀다.
