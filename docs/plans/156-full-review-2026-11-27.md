## 배치 A — 백엔드 실버그 (우선, PR 1개)

**A1 [확인] 백그라운드 동기화가 오래된 계좌 행을 되써서 삭제를 되돌린다** — `backend/app/services/accounts/sync_all_service.py:75`
- 잡 시작 때 읽은 detached `account`를 `db.merge(account)`로 새 세션에 넣는다. `expire_on_commit=False`라 모든 컬럼이 로드된 상태여서, merge가 stale 값(`is_active=True`, 암호화 키)을 그대로 덮어쓴다. `delete_account`(`api/v1/assets.py:387`)는 sync 락을 잡지 않는다.
- 시나리오: 동기화 도중 계좌 삭제 → 동기화 커밋이 계좌를 활성으로 되돌리고 App Key를 복구. 이름·ISA·목표 포트폴리오 수정도 같은 식으로 되돌아간다.
- 수정: merge 대신 `await db.get(AssetAccount, account.id)`(또는 `select ... where id, is_active`)로 새로 읽고, 없거나 비활성이면 건너뛴다. 테스트: 잡 시작 후 계좌를 비활성화한 뒤 sync_one을 실행하면 `is_active`가 False로 유지되는지(실 DB 테스트가 있으면 `tests/test_real_db_*` 패턴으로).

**A2 [확인] 토스 매수가능금액 조회의 모든 `TossApiError`를 0원으로 저장한다** — `backend/app/toss/balance.py:84-95`

**A7 KIS/키움 토큰 동시 발급** — `providers/_token_cache.py:40-63`

**A8 정리**: `asset_service.py:94` `_retry_provider_sync` docstring이 없는 재시도를 설명한다 → 실제 동작대로 고친다. `delete_account`(`api/v1/assets.py:387`)에 다른 CUD 라우트와 같은 `@limiter.limit`을 붙인다.

### 배치 A 결과 (2026-11-27)
- A1~A7 구현. A1은 `db.get`으로 다시 읽고 비활성이면 건너뛴다. mock 테스트와 실 DB 테스트를 추가했다(`test_batch_sync_does_not_revert_concurrent_account_edits` — 이름 수정은 남고, 삭제 계좌는 건너뜀).
- A2 토스 토큰 오류 코드는 특정할 수 없었다. 원화 실패는 동기화 실패로 올리고, 달러 실패는 None(기존 `deposit_usd` 유지, 합계 보정은 `asset_service`)으로 처리했다.
- A3 표식 `OUTCOME_UNKNOWN_MARKER`("여부 불명")를 `http_client`의 응답 유실 메시지 두 곳과 공유한다. 결과 유실 leg(`plan_sweeps`)에 더해, 주문 중 하나라도 응답 유실이면 `_fail_leg_without_fills`도 "결과 확인 필요"로 알린다. 메일 `error_message`는 escape 처리했다.
- A5 `format_sync_error(예외)`는 `public_error_message`를 거친다(`CircuitOpenError`를 허용 목록에 추가). 내부 재귀를 피하려고 `_redact_truncate`로 분리했다.
- A6 계획을 바꿨다. 발송 전에 전체 TTL로 선점하면 발송 중 크래시 때 그달 리포트가 막힌다. 그래서 발송 뒤 **선점 연장을 인앱 이력과 분리해 먼저 커밋**(1회 재시도)하도록 했다. 챌린지 결산은 미커밋 claim이 동시 실행 락 역할이라 구조 변경이 커서 이관한다(remaining-tasks).
- A7 `get_or_fetch_token`의 캐시·DB 미스 경로를 `single_flight_fetch`로 감쌌다(3사 공용).
- A8은 문제없음: `_retry_provider_sync`에는 tenacity `@retry` 데코레이터가 있어 docstring이 맞다. rate limit은 계좌 생성·수정에도 없어 삭제만의 누락이 아니고 비용 대비 낮다.
- 덤: `test_market_hours::test_defaults_to_current_time_when_now_omitted`는 기대값을 16시로 고정해 조기 폐장일(오늘 블랙프라이데이 13시)에 깨졌다. 그날의 `nyse_close_time`과 비교하도록 고쳤다.
