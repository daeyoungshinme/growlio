# 121 — 달러 환전 계획 알림을 행동 가능하게 (2026-11-10)

## 배경

사용자는 달러 환전 계획(plans/96)으로 환전 구간을 정하고 알림을 받아 적극적으로 환전하려 한다. 검토 결과 다음 문제가 있었다.

| # | 문제 | 처리 |
|---|---|---|
| P1 | 5분 환율 알림 잡이 웹 프로세스 안에서 돈다. Render 무료 플랜이 잠들면 멈춘다(keep-alive 실측 2~9시간) | **배치 D** — 외부 핑 등록 확인(코드 밖) |
| P2 | 알림에 환전할 금액이 없고 계획 화면 링크도 없다 | **배치 A 완료** |
| P3 | 필요 달러가 정액 적립액(`dca_amount_krw`) 대신 전역 월 적립액 기준이다 | **배치 B 완료** |
| P4 | 보유 달러가 하루 1~2회 동기화 값이라 환전 직후 계획이 틀린다(중복 환전 유도) | **배치 B 완료** |
| P5 | 목표가 바뀌어도 옛 BELOW 알림이 남아 쌓이고, 계획에서 만든 알림인지 구분할 수 없다 | **배치 A 완료** |
| P6 | 적립일 직전 달러 부족 알림이 없다 | plans/120이 정액 적립에 한해 이미 처리(`dca_cash_shortfall_service` 달러 판정). 월 적립액 기준 사용자는 배치 C |
| P7 | 카드가 기본 접힘이고 홈 "지금 할 일"에 환전 항목이 없다 | **배치 C 완료** |

## 배치 A — 구현 (완료)

| 영역 | 내용 |
|---|---|
| 모델·마이그레이션 `fx1` | `exchange_rate_alerts`에 `source`(MANUAL 기본 / FX_PLAN), `planned_usd`, `portfolio_id`(FK SET NULL, 인덱스) 추가. 컬럼 추가만이라 옛 코드와 호환 |
| `fx_plan_service.sync_fx_plan_alerts` | `PUT /invest/fx-plan/alerts`(20/min). 포트폴리오 소유 확인(404) → 사용자 단위 inproc 락(409) → 같은 포트폴리오의 활성·미발동 FX_PLAN 알림을 목표 목록에 맞춘다. 같은 목표면 금액을 갱신하고, 새 목표면 BELOW 1회 알림을 만들고, 목표에서 빠지면 삭제한다. 같은 목표의 활성 MANUAL BELOW 알림이 있으면 만들지 않는다(`skipped_manual`). **MANUAL 알림은 절대 바꾸거나 지우지 않는다.** 발동된 계획 알림은 이력으로 남긴다. 50개 상한 검사. 목표 비교는 센트 단위 정수 키 |
| 발동 알림 | `exchange_rate_service`: FX_PLAN이고 금액이 있으면 메일 제목·본문에 "$X(약 Y원) 환전"과 계획 화면 링크(`fx_plan_link`, 인코딩)를 싣고, 푸시 제목은 "환전 계획 구간 도달", `data.type=FX_PLAN`으로 보낸다. 알림 이력 메시지에도 금액을 남긴다. `notify_and_record_trigger`에 `push_data` 인자를 추가했다 |
| 프론트 | `FxPlanCard`가 순차 POST 대신 `syncFxPlanAlerts`를 쓴다. 등록 상태는 목표와 금액($1 이내)을 비교해 판정한다. 목표·금액이 바뀌면 "알림을 새 계획으로 바꾸기"를, SUFFICIENT면 "이 계획으로 등록한 알림 N건 해제"를 보여 준다. 직접 등록한 같은 목표는 "직접 등록한 알림 있음"으로 표시한다. 설정 › 환율 알림 목록에 "환전 계획 · $X" 표시. 푸시 `FX_PLAN` → 계획 › 적립 계획 |

### 알려진 한계

- 121 이전에 계획 카드로 등록한 알림은 출처를 알 수 없어 MANUAL로 남는다. 카드에 "직접 등록한 알림 있음"으로 보이고 계획 동기화가 바꾸지 않는다. 금액이 실린 알림으로 바꾸려면 설정 › 환율 알림에서 지우고 다시 등록해야 한다.
- 계획 금액은 등록 시점 값이다. 환율·보유 달러가 바뀌면 카드가 "새 계획으로 바꾸기"를 제안하지만 자동으로 갱신하지는 않는다.

## 배치 B — 구현 (완료)

| 영역 | 내용 |
|---|---|
| 필요 달러 기준 | 포트폴리오에 활성 정액 적립 자동매수 알림(`DCA_AUTO_BUY_PRESET` + `dca_amount_krw`)이 있으면, 알림마다 `dca_cash_shortfall_service.fixed_amount_needs`로 해외 몫(달러)을 구해 합한다. ISA·연금 계좌는 해외 종목을 다른 종목으로 사므로 몫이 0이다 → 합이 0이면 `NO_OVERSEAS`. 정액이 없으면 기존 월 적립액 × 해외 비중. 응답 `deposit_source`(DCA_AMOUNT / MONTHLY_GOAL) |
| 실시간 보유 달러 | 연결 계좌(없으면 활성 브로커 계좌 전체)와 정액 적립 실행 계좌의 합집합에서, KIS·키움 계좌(계좌번호 있음)는 `usd_buying_power.fetch_usd_buying_power`로 실시간 조회한다. 캐시는 `usd_buying_power_key(user, account)` 2분이고, 계좌 동기화 무효화(`invalidate_asset_account_caches`)가 사용자 단위로 지운다. 실패·토스·수기 계좌는 동기화 값을 쓴다. 응답 `held_usd_is_live`(달러가 있는 계좌를 모두 실시간으로 읽었는지) |
| 환전 대기 부족분 | 이 포트폴리오의 `WAITING_FX` leg `required_usd` 합 − 보유 달러 = `waiting_fx_usd`. 필요 달러는 최소 이 값이고, `compute_fx_plan(..., urgent_usd)`가 "지금" 구간을 최소 이만큼으로 늘린다(위치가 없으면 "지금" + "적립일에 환전") |
| 프론트 | 산식 문구가 정액이면 "정액 적립 월 X원의 해외 몫"이고, 보유 달러 뒤에 "(실시간)" 또는 "(동기화 기준)"을 붙인다. 환전 대기가 있으면 주황 안내와 "대기 중인 매수 보기"(리밸런싱 › 이력) 링크를 보여 준다 |

### 알려진 한계 (B)

- 실시간 조회는 화면을 열 때마다 KIS·키움 해외잔고 API를 계좌 수만큼 순차 호출한다(2분 캐시). 토큰 발급이 DB commit을 하므로 병렬화하지 않았다.
- 실시간 조회 실패는 `usd_buying_power`가 Sentry에 보고한다(자격증명 누락 계좌가 있으면 화면 열 때마다 보고될 수 있음).

## 배치 C — 구현 (완료)

| 영역 | 내용 |
|---|---|
| 홈 "지금 할 일" `FX_PLAN` | `action_items_service._fx_plan_items`가 최근 `FX_PLAN_ACTION_DAYS`(3)일(KST, 오늘 포함) 안에 발동한 계획 알림을 **한 행**으로 합친다. 예: "목표 환율 도달 — $550 환전", 상세 "1,320원 · 1,300원 이하 도달 · 환전 후 계좌를 동기화하세요", HIGH. 환전 여부는 알 수 없어 기간으로 끈다. 쿼리는 `_recent_fx_plan_alerts`로 분리했다(테스트 patch 지점) |
| 카드 펼침 | 메일 링크·푸시 딥링크·"지금 할 일" 링크에 `#fx-plan` 해시를 붙였다. `InvestPlanPage`가 이 해시로 들어오면 접어 둔 카드를 펼치고, 로딩이 끝난 뒤 스크롤한다. 계획 알림이 있다는 이유만으로 항상 펼치지는 않았다 — 해시 진입이 행동 시점과 정확히 겹치고, 저장된 접힘 선택을 덮어쓰지 않는다 |

### 판단 — 월 적립액 기준 사용자의 적립일 달러 부족 알림

만들지 않았다. 정액 적립은 plans/120이 이미 원화·달러를 따로 비교해 사전 알림을 보낸다. 월 적립액 기준(정액 아님) 자동매수는 예수금 전체로 목표 비중을 채우는 방식이고, 사전 판정도 원화+달러 환산 합계로 한다. 여기에 달러만 따로 부족하다고 알리면, 해외 몫 금액이 정해져 있지 않아 기준이 모호하다. 필요하면 정액 모드 전환을 안내하는 편이 맞다.
