# 149. 달러 환전 계획을 계획 › "환전" 탭으로 분리 (2026-11-23)

## Context
사용자 요청: "계획탭에 적립계획에 달러환전 계획은 따로 두는 게 좋을 것 같다, 검토."

환전 계획은 `적립 계획` 탭 안의 접힘 카드였다. 검토 결과:
- 화면 결합이 거의 없다 — `FxPlanCard`는 자기 쿼리(`fxPlanQuery`·`exchangeRateAlertsQuery`·`accountsQuery`)를 받고 페이지에서 받는 건 `onEditGoal` 하나. 월 필요 달러는 서버(`fx_plan_service._build_fx_plan`)가 적립 설정에서 계산하므로 탭이 달라도 같다.
- 카드가 적립 분석(dca-analysis) 로딩·실패 게이트 안에 있어 적립 분석이 느리거나 실패하면 환전 계획도 안 보였다.
- 추가 환전(`FxExtraNeedsSection`, 여행 등)은 적립과 무관하다.
- 딥링크가 해시로 접힌 카드를 강제로 펼치고 스크롤하는 장치에 의존했다.

## 결정(사용자)
- 탭 이름 "환전", 위치는 적립 계획 바로 뒤: `적립 계획 | 환전 | 배당 계획 | 절세 | 챌린지`.
- 낙폭 추매 안내는 적립 탭에 그대로 둔다.

## 변경
- 프론트: `INVEST_PLAN_TABS`에 "환전". `InvestPlanPage`의 환전 탭은 펼친 카드(접기 없음, `growlio:invest:fxPlanOpen` 미사용)로 적립 분석과 무관하게 그리고, 탭 진입 시 기본 계획을 프리페치. 푸시 `FX_PLAN` → `investPlanUrl("환전")`.
- 옛 링크 호환: `?tab=적립 계획#fx-plan`(이미 발송된 메일·푸시)은 `legacyTabRedirect.legacyInvestPlanTab`으로 환전 탭을 열고 URL도 바꾼다.
- 백엔드: `action_items_service._LINK_FX_PLAN`·`email_service.fx_plan_link` → `?tab=환전`(해시 없음). 마이그레이션 없음.

## 검증
- frontend lint·typecheck·format:check·vitest 전체 통과, backend ruff·mypy·관련 pytest 통과.
- 수동 미확인: 390px에서 5개 pill 탭 라벨, 옛 링크 진입.
